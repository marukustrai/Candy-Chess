# Contributing to Candy Chess

This project is meant to be easy to join, even if you are new to GitHub.

## Where to work

- Rules and design docs go in `docs/`
- Python board and move logic goes in `engine/`
- The interactive board and candy visuals go in `frontend/`

## A simple workflow

1. Pick an open issue (start with the Phase 1 issues if you are new).
2. Create a branch with a short name, such as `docs/legal-moves`.
3. Make your changes in the matching folder.
4. Open a pull request and describe what you changed in plain language.
5. Wait for a review before merging.

## Phase 1 scope

Phase 1 uses standard chess rules. Only the visuals are candy-themed. Please don't add Phase 2 twists (sugar rush, melting, and so on) until Phase 1 is playable.

## Style tips

- Prefer clear names and short comments over clever code.
- Add a brief note in your folder's README if someone else will need setup steps.
- Ask questions on the issue if anything is unclear.
